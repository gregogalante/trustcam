The three possible results

✓

Verified

This is the exact file that came out of the camera: the proof it carries inside checks out against its hardware key. Authentic and untouched — the strongest claim we make.

!

Origin traced

The invisible mark tells us which device this image comes from. Photos sealed by recent app versions also carry a content checksum inside the mark: it survives compression but breaks when what the image shows is changed — so we can usually tell a re-shared copy from an edited one. Never proof of authenticity, only of origin.

✕

No proof found

Either the file was never captured with TrustCam, or too little of the original is left — say a crop that keeps less than half of the image, or a screenshot of a small preview. We can't tell these two apart, so we claim nothing.

Prefer your terminal?

Same verification from the command line, fully local. It also scans re-encoded videos for the invisible mark (needs onnxruntime, pillow and ffmpeg for that part — the seal check needs only openssl):

curl -sO https://trustcam.gregoriogalante.com/verify.py
python3 verify.py photo.jpg          # proof-trailer check
python3 verify.py --scan video.mp4   # + invisible-mark scan
The proof travels inside the file itself; the public device registry maps invisible marks back to registered devices. Everything is verified locally — this site is fully static.

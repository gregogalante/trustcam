How it works

1 · Capture

Photo or video, from the TrustCam app. The file's cryptographic fingerprint (SHA-256) is computed as it's written.

2 · Sign in silicon

The fingerprint is signed by a key generated inside the phone's secure element. The key physically cannot leave the chip — no malware, no cloud breach can steal it.

3 · Watermark

An invisible signal carrying the proof's identity is woven into the pixels themselves. Re-encoding, scaling, compressing — it survives what social platforms do to files.

4 · Anyone verifies

Drop any copy of the file on the public verifier: owner, device, hardware security level and capture time — or proof that it was tampered with.

Two layers, because one is never enough

Signatures prove integrity but die on re-encoding. Watermarks survive re-encoding but can't prove integrity. TrustCam is the first mobile capture system that ships both.

Layer 1 — Hardware signature

ECDSA P-256 in the secure element, with Android Key Attestation proving the key lives in tamper-resistant silicon. Byte-exact files verify against it — any single-bit change is detected.

Layer 2 — Invisible watermark

A 256-bit error-corrected payload embedded in the pixels (Meta's VideoSeal, state of the art in the open literature). When platforms strip everything else, the pixels still testify.

Honest by design

What a proof means

“This exact file was recorded by this specific device, bound to this account, at this time — and is unmodified since.” Every claim is re-verified cryptographically on every check; the database is treated as a claim, the signature as the evidence.

What it doesn't

No capture system can prove the scene was real — a camera filming a screen signs what its sensor sees. We say precisely what we can prove and nothing more. In this market, overclaiming is fatal; our threat model is public.
